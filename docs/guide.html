Guide

Install, run, and run on an HPC. You do not need to know anything about containers or workflow managers: agmp_gwas handles both.

01Install

You need Linux or macOS (Windows through WSL), Apptainer or Singularity (most HPC clusters have it: try module load apptainer), internet access, about 2 GB of disk per release and 6 GB of memory.

git clone https://github.com/nhlamulokhoza/AGMP_GWAS.git
cd AGMP_GWAS
./agmp_gwas setup      # once: builds agmp_gwas_container (about 5 minutes)
./agmp_gwas check      # ends with "All good." when you are ready

That is the whole installation. The folder stays tidy:

AGMP_GWAS/
├── agmp_gwas                     the only command you use
├── agmp_gwas_container.sif       made by setup: the workflow and all its software
├── container/                    the recipe for the container
├── workflow/                     Snakefile, scripts, default settings
├── docs/                         this documentation
└── results/  cache/  logs/       made by runs

02The container

agmp_gwas_container.sif is one file that holds the whole workflow and every piece of software it needs, at fixed versions. Every step runs inside it, so results do not depend on what else is installed, and anyone with the same container gets the same results. You never enter it yourself.

The container plus the agmp_gwas launcher is a complete install. To run on another computer, copy those two files; nothing else is needed.

If the container cannot be built

Some clusters do not let users build containers. Then either build it on another computer with Apptainer and copy the .sif file next to agmp_gwas, ask your HPC support to enable "fakeroot" builds, or run ./agmp_gwas setup --no-container to use a Python environment with the same package versions instead.

03Run

./agmp_gwas run

This processes the latest GWAS Catalog release and writes results/<release date>/. When it finishes it prints where the results and the report are. If that release is already done, it finishes at once; when the Catalog publishes a new release, the same command processes it.

./agmp_gwas run --dry-run    # show what would run, run nothing

Results, caches and logs go to the work directory, which is the AGMP_GWAS folder unless you give another: --workdir /scratch/me/agmp.

04Options Optional

Every option has a default, so ./agmp_gwas run alone is a complete run. The command builder lists every option with check boxes and writes the command for you.

The rest: ./agmp_gwas run --help.

05Compare with earlier data Optional

Comparison is off unless you give the path to the earlier data. Without it every record counts as new, and no earlier output is read. There are two kinds, and you can use either or both.

Against data already in AGMP

Give the path to the file(s) imported into AGMP before: CSV or parquet with an id column. Repeat --previous for several files.

./agmp_gwas run --previous late2024_import/gwas_data_15092024.csv

Variants found there are marked as not new, and three new-only files are written: intergenic, non_intergenic and combined.

Against an earlier release

Give the path to the results folder of an earlier run:

./agmp_gwas run --compare-release results/2026-06-19

This adds a quality check that stops the run before export if the number of records fell by more than 10%, which catches truncated downloads and changes to the Catalog's file format.

06Choose files and columns Optional

Files. Every output file is written as CSV unless you say otherwise. Pick each file's formats with two lists: --csv and --excel. Each takes all, none, file names, or all minus some.

./agmp_gwas run --excel ethnicity_report             # everything as CSV, plus this one as Excel
./agmp_gwas run --csv all,-combined --gzip           # all but one, compressed
./agmp_gwas run --csv none --excel combined_with_old # a single Excel file

Excel is slow for the large files and holds at most 1,048,575 rows. The command builder has a CSV and an Excel switch for each file.

Columns.

Files have the 30 standard AGMP columns unless you choose fewer. See every column, where it comes from and how it is made with ./agmp_gwas columns (or ./agmp_gwas columns geographical_region for one), or in the column guide.

./agmp_gwas run --columns id,PUBMEDID,phenotype,p-value,geographical_region

Columns are always written in the standard order. Changing them re-runs only the export: nothing is downloaded or rebuilt. The report's column chooser writes this command for you, with a preview of the data.

Files for the AGMP import need all 30 columns. Use a column choice for your own analyses.

07On an HPC Only on a cluster

Do not run on a login node. Submit a job instead:

./agmp_gwas run --slurm

It writes and submits the job script, then prints the job number and its log file (logs/agmp_gwas_<job>.out). Add your usual options after --slurm, and these for the job's resources:

OptionDefaultMeaning
--time08:00:00Time limit
--mem6GMemory
--cores6CPU cores
--partitioncluster defaultPartition or queue
--accountnoneAccount, if your cluster needs one
./agmp_gwas run --slurm --partition batch --previous imports/old.csv

Internet on compute nodes. The workflow downloads data while it runs. Check from a short interactive job (srun --pty bash, then ./agmp_gwas check). If compute nodes are offline, see Offline.

Other folders. The container sees the work directory and any file you name on the command line. To make another folder visible, export AGMP_GWAS_BIND=/scratch first.

08Time and space

First runLater releases
Time, 6 coresabout 4 hoursabout 1 hour
Memorypeak about 1.5 GB; ask for 6 GB
Diskabout 1 GB of CSV per release (about 160 MB as csv.gz), plus small caches

Most of the first run is spent waiting for Ensembl to answer lookups. Every answer is kept in cache/, so later releases only look up what is new. Keep that folder.

09Offline Optional

Without internet, download the two GWAS Catalog files elsewhere (FTP, releases/latest/) and point the workflow at them. New variants and genes cannot be looked up offline, so this works best once the caches are filled by an earlier online run.

./agmp_gwas run --release 2026-11-02 \
  --local-associations gwas-catalog-associations_ontology-annotated-full.zip \
  --local-ancestry gwas-catalog-ancestry.tsv --no-triage

10Re-run and update

  • New Catalog release: ./agmp_gwas run. It gets its own folder.
  • Rebuild a release (after updating AGMP_GWAS): ./agmp_gwas run --rebuild. Cached lookups are kept.
  • Interrupted run: run the same command again. If it reports a lock, run once with --unlock.
  • Update AGMP_GWAS: git pull, then ./agmp_gwas setup --rebuild to rebuild the container with the new version.

11Reproduce a run

Every release folder holds run_settings.yaml (every setting used) and release.json (the source files with their release dates, sizes and ETags). With the same container and those settings, --release gives the same records. ./agmp_gwas version prints the version inside the container.
