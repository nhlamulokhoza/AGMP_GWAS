01Study selection

Selection works on study populations: one row of the GWAS Catalog ancestry file, which is one stage (initial or replication) of one study. Each row takes the first route that applies:

RouteRuleStatus
ExplicitBroad ancestral category matches Africa|Greater Middle Eastern (case-insensitive)explicit
LabelCategory is NR or Other, as whole wordsunresolved
CountryA country of recruitment or origin is African (workflow/config/regions.yaml, with aliases)unresolved
DescriptionThe row's own sample description names African or diaspora samples. Only for studies with no explicit or label row, so multi-ancestry studies are not pulled in by a passing mention.unresolved

Associations are then joined to the selected populations by study accession. Unresolved records are kept, flagged, and passed to the curation queue.

02Variant IDs

The Catalog's SNPS field is split into tokens and each is classified: rsid (kept), merged_updated (replaced by the current rsID), synonym (rsA/rsB, resolved to the current rsID), positional (converted where safe, below), interaction (rs1 x rs2, excluded) and other (HLA alleles, structural variants, excluded).

Converting positional IDs

dbSNP is dense enough that a position alone often matches some variant by chance, so the conversion is conservative:

  1. Genome build per paper. Up to 25 positions from the paper are looked up on GRCh38 and GRCh37 (Ensembl /overlap/region). The build where variants carrying the reported allele are found clearly more often (at least 50% of the sample, and 1.5 times the other build) is the paper's build. With no clear build, the paper's positions stay unconverted.
  2. One unique match. A position is accepted only if exactly one rsID starts there and lists the reported risk allele (and the reference and alternative alleles when the ID gives them).
  3. Genes come from the same lookup, named genes first. The mapped gene is built in the Catalog's style: genes the variant falls in, otherwise the nearest named gene on each side within 500 kb.

Positions Ensembl rejects as invalid for the build (for example beyond the end of a chromosome) are cached as having no match, so they are not retried.

03Annotation

Genes. Each Ensembl gene ID gets its name and description from Ensembl (/lookup/id, GRCh38 then GRCh37 for retired IDs), and its UniProt accession and function from reviewed Swiss-Prot entries that cross-reference it, then UniProt ID mapping, then UniProt search.

Consequence. Where the Catalog gives no CONTEXT, Ensembl VEP's most severe consequence over all transcripts on the primary GRCh38 assembly is used, with up/downstream calls written as intergenic_variant as the Catalog does. On 600 variants that do have a Catalog CONTEXT, this agreed exactly for 91%; the rest are borderline cases such as intron_variant against non_coding_transcript_exon_variant.

Regions. Recruitment countries are mapped to AGMP regions with workflow/config/regions.yaml; when none maps, the broad ancestral category is used.

04Records

A record is one variant, one trait, one study population and one gene. Identical records are reduced to one, keeping the smallest p-value. With --previous, is_new is false for variants found in the previous files, matched on both the final and the reported ID.

06Curation queue

Unresolved studies are grouped by publication. Their text is scored against a lexicon of about 400 weighted terms (workflow/config/lexicon.tsv): African countries, demonyms, diaspora terms, regions, ethnolinguistic groups and known cohorts. The text is read in order: the Catalog's sample descriptions, the PubMed abstract, then, for papers still unclear, methods sections of open-access full text from Europe PMC. Only matching sentences are kept. A score of 4 or more is high priority, 2 or more medium. Issues are judged per study accession, so a paper is not flagged for ancestry when its other populations are explicit.

ColumnMeaning
priority, scorehigh, medium or low, and the evidence score behind it
issuesWhat is unresolved: ancestry, origin and/or ethnicity
n_variants_*, n_studies, study_accessionsHow much curating the paper would settle
candidate_regions, candidate_countries, candidate_ethnolinguistic, cohortsSuggestions from the text
evidence_sources, evidenceWhere they were found, and the sentences
curator_decision, curator_notesLeft empty for the curator

The queue only suggests: nothing it finds reaches the AGMP files without a curator's decision.

07Unmapped variants

unmapped_variants.tsv lists every variant ID that did not become an rsID, so nothing is lost silently. rescue_status says why: no_allele (a position without an allele), no_unique_match (no single known variant there with the allele), build_undetermined (the paper's build is unclear), lookup_pending (continued next run), or empty for interaction terms and other IDs.

08Caches

Lookups are cached in cache/ in the work directory, so each question is asked once, reruns give the same answers, and past results do not change when a web service does.

09Settings

Defaults live in workflow/config/config.yaml, commented throughout. The run options cover the common changes. For anything else, put only the keys to change in a YAML file and pass --settings my.yaml:

10Reproducibility

  • Software and code: agmp_gwas_container is built from a fixed Python image (3.13.5) with the exact package versions in container/requirements.txt, and holds the workflow itself. It records what it installed in /opt/AGMP_GWAS/installed.txt.
  • Data: release.json records each source file's URL, release date, last-modified time, ETag and size.
  • Settings: run_settings.yaml holds every setting used.
  • Web services: answers are cached, so a rerun does not depend on them.

For developers

  • workflow/scripts/columns.py is the single description of the output: the report, the columns command and these pages all read it. If you change how a column is made, update its entry, then run ./agmp_gwas docs.
  • To try code changes without rebuilding the container: AGMP_GWAS_DEV=1 ./agmp_gwas run … uses workflow/ from the folder. Rebuild with ./agmp_gwas setup --rebuild before real runs.
  • To add a country or alias, edit workflow/config/regions.yaml. Countries with no region are listed in release.json.
  • To publish these pages, serve the docs/ folder (for example with GitHub Pages).
